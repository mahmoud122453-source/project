# دليل التشغيل — التحكم بمستوى الصوت بإيماءة اليد

هذا الدليل يصف الأوامر التي نُفّذت فعليًا على الجهاز التالي:

- النظام: Windows 10 Pro، الإصدار 10.0.19045، 64-bit
- Python: 3.12.0
- pip داخل البيئة الافتراضية: 26.2.1
- الكاميرا: Integrated Webcam
- مخرج الصوت: Speakers (Realtek(R) Audio)

المشروع يتحكم بمستوى صوت مخرج التشغيل الافتراضي في Windows فقط. PyCaw لا يوفّر هذا المسار على macOS أو Linux.

## 1. إصدار Python

استخدم Python 3.12. التحقق:

```bat
py -3.12 --version
```

النتيجة المتحقَّق منها: `Python 3.12.0`.

## 2. البيئة الافتراضية

من مجلد المشروع:

```bat
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
```

النتيجة المتحقَّق منها بعد الترقية: `pip 26.2.1`.

لا تستخدم Python العام للجهاز بعد إنشاء `.venv`. كل أوامر التشغيل التالية تستخدم مفسر البيئة.

## 3. التبعيات — لماذا لا نثبّت الأسماء بلا إصدار

ملف `requirements.txt` الأصلي كان بلا إصدارات. تثبيته كما هو على هذا الجهاز أعطى:

| الحزمة | ما ثبّته pip | النتيجة |
| --- | --- | --- |
| mediapipe | 1.0.1 | `AttributeError: module 'mediapipe' has no attribute 'solutions'` |
| pycaw | 20260927 | `AttributeError: 'AudioDevice' object has no attribute 'Activate'` |
| opencv-python | 5.0.0.93 | الاستيراد نجح |
| numpy | 2.5.3 | الاستيراد نجح |
| comtypes | 1.4.17 | الاستيراد نجح |

الكود الأصلي يستدعي `mp.solutions.hands` و`devices.Activate(...)`. لذلك تُثبَّت إصدارات ما زالت تقدّم هاتين الواجهتين، بدل إعادة كتابة MediaPipe أو PyCaw.

## 4. التثبيت المتحقَّق منه

```bat
.venv\Scripts\python.exe -m pip install mediapipe==0.10.21 --no-deps
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

سبب `--no-deps`: بيانات حزمة MediaPipe 0.10.21 تطلب `jax` و`jaxlib` و`sentencepiece` و`numpy<2`. مسار `Hands` القديم في `HandTrackingModule.py` لا يستورد هذه الحزم. فرض `numpy<2` يتعارض مع NumPy 2.5.3 وOpenCV 5 اللذين اكتمل بهما اختبار الإطارات. محاولة تثبيت `jaxlib` على هذا الجهاز انقطعت بسبب الشبكة وقفل ملف مؤقت، ولم تكن مطلوبة لتشغيل الكاشف.

`drawing_utils` يستورد `matplotlib`، لذلك `matplotlib==3.11.2` موجود في `requirements.txt` ويُثبَّت مع تبعياته تلقائيًا.

الإصدارات بعد التثبيت الناجح:

`pycaw==20240210` يسحب `psutil` تلقائيًا. في هذا الإصدار تُرجع `AudioUtilities.GetSpeakers()` كائن `IMMDevice` الذي يملك `Activate()`. هذا هو الاستدعاء المكتوب في `Gesture_Volume_Control.py`.

## 5. متطلبات الكاميرا

- كاميرا فيزيائية ظاهرة لـ Windows. على هذا الجهاز: Integrated Webcam، الحالة OK.
- التطبيق يفتح الفهرس `0` فقط: `cv.VideoCapture(0)`.
- الدقة التي أرجعتها الكاميرا في الاختبار: 640×480.
- إذا فشل الفتح يرفع السكربت: `Exception: Couldn't open the webcam`.
- لا يوجد في الكود اختيار كاميرا أخرى، ولا معالجة خاصة إذا كانت الكاميرا مشغولة. على هذا الجهاز نجح فتح `VideoCapture(0)` مرة ثانية بينما الالتقاط الأول ما زال مفتوحًا، أي أن الجهاز لا يرفض المشاركة.

## 6. متطلبات Windows والصوت

- Windows مع مخرج تشغيل افتراضي. الجهاز المختبَر: Speakers (Realtek(R) Audio).
- PyCaw وcomtypes يتحدثان مع Core Audio عبر COM.
- المدى الفعلي الذي أعاده `GetVolumeRange()` على هذا الجهاز: من `-65.25` dB إلى `0.0` dB، والخطوة `0.03125`. الكود يأخذ أول قيمتين فقط.
- ضبط مستوى عبر `SetMasterVolumeLevel(-20.0, None)` غيّر المستوى الفعلي من `-1.21875` dB (النسبة السلمية `0.9219`) إلى `-20.0` dB (النسبة السلمية `0.2581`)، ثم أُعيدت القيمة الأصلية. هذا تحقق من مسار Windows نفسه، وليس من إيماءة يد.

## 7. التحقق من MediaPipe

```bat
.venv\Scripts\python.exe -c "import mediapipe as mp; print(mp.__version__); print(mp.solutions.hands); import HandTrackingModule as htm; d=htm.HandDetector(detectionCon=0.7, trackCon=0.7); print(type(d.hands).__name__); d.release()"
```

النتيجة المتحقَّق منها:

- الإصدار `0.10.21`
- `mp.solutions.hands` موجود
- `HandDetector` ينشئ كائن `Hands`
- يظهر تحذير TensorFlow Lite / feedback manager. التحذير لم يوقف التشغيل

MediaPipe 1.0.1 يفشل عند السطر `self.mpHands = mp.solutions.hands`.

## 8. أمر التشغيل

```bat
.venv\Scripts\python.exe Gesture_Volume_Control.py
```

هذا هو الأمر الموثَّق في المشروع، مع مفسر البيئة الافتراضية. عند النجاح:

- تُهيَّأ واجهة الصوت قبل فتح الكاميرا
- تُفتح نافذة عنوانها `Hand`
- تُرسم معالم اليد إن وُجدت يد
- يُرسم شريط الصوت بالنسبة المئوية
- لا يُغيَّر صوت Windows إلا عندما يُرجع `findPositions` معالم

في الاختبار الحي لم تكن هناك يد أمام الكاميرا: 20 إطارًا بلا معالم، ونافذة `Hand` ظهرت، ومستوى Windows بقي `-1.21875` dB.

## 9. مفتاح الخروج

الكود يخرج فقط عندما تكون القيمة:

```python
cv.waitKey(1) & 0xFF == ord('p')
```

أي الحرف اللاتيني `p` (الرمز 112).

على هذا الجهاز تخطيط لوحة المفاتيح هو العربية (`0x0401`). ضغط المفتاح الفيزيائي P وصل إلى `waitKey` بالقيمة `205`، وهذه القيمة لا تطابق `ord('p')`، لذلك لم تُغلق النافذة.

إغلاق النافذة بزر X لا يُنهي الحلقة. الحلقة تنتظر الحرف `p`.

ما تم التحقق منه: إرسال `WM_CHAR` بالحرف `p` إلى نافذة `Hand` أنهى `Gesture_Volume_Control.py` برمز خروج `0`، ثم أمكن فتح الكاميرا مرة أخرى.

للخروج أثناء الاستخدام: اجعل نافذة الفيديو في المقدمة، حوّل لغة الإدخال إلى الإنجليزية، ثم اضغط `p`.

`HandTrackingModule.py` عند تشغيله وحده يستخدم المفتاح نفسه، ويعرض FPS. تطبيق الصوت لا يعرض FPS.

## 10. أعطال الكاميرا والصلاحيات

- لا كاميرا، أو فهرس خاطئ: `VideoCapture(99)` أعاد `isOpened() == False`. السكربت الأصلي عندها يرفع الاستثناء قبل الحلقة، ولا يستدعي `cap.release()`.
- الكاميرا مشغولة ببرنامج آخر: لا يوجد فحص في الكود. على هذا الجهاز لم يُرفض الفتح الثاني.
- إطار أسود أو صلاحية مرفوضة من Windows: افتح إعدادات الخصوصية في Windows وتأكد أن الوصول إلى الكاميرا مسموح لتطبيقات سطح المكتب. في الاختبار كانت الصورة حقيقية: متوسط السطوع `72.5` والانحراف المعياري `30.4`، وليست إطارًا أسود.
- ظهر مرة تحذير MSMF أثناء القراءة (`OnReadSample` بالحالة `-1072873821`) ومع ذلك اكتملت 20 قراءة ناجحة. إذا تكررت القراءة الفاشلة يخرج الكود من الحلقة عبر `if not ret: break` ثم يحرر الكاميرا.

## 11. أعطال الصوت

- لا مخرج تشغيل افتراضي: `GetSpeakers()` أو `Activate()` سيفشل عند الإقلاع، قبل فتح الكاميرا. لا توجد `try/except` حول هذا الجزء.
- PyCaw أحدث من 20240210: يفشل عند `Activate`. لا تستبدله بإصدار 20251023 أو 20260927 مع هذا الكود.
- كتم الصوت من Windows يبقى كما هو. الكود لا يستدعي `SetMute` ولا `GetMute`.
- النسبة على الشاشة ليست نسبة شريط Windows. مسافة الإصبع `110` بكسل تُعرَض `50%` وتقابل `-32.625` dB. عند ضبط هذه القيمة كان المقياس السلمي في Windows `0.1047`، أي حوالي 10% على مقياس 0–1، وليس 50%.

## 12. ما لم يُختبر بيدك

لم تكن هناك يد داخل الإطار أثناء الاختبار الحي. لذلك لم يُتحقق بصريًا من رسم المعالم، ولا من تغيّر صوت Windows نتيجة تقريب الإبهام والسبابة. مسار الحساب ومسار `SetMasterVolumeLevel` اختُبرا منفصلين، ومسار «لا يد فلا تغيير للصوت» اختُبر أثناء تشغيل التطبيق.
