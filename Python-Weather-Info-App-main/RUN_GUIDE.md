# دليل التشغيل — تطبيق الطقس

هذا الدليل يشرح كيف تشغّل النسخة الموجودة في هذا المجلد. لا تضع مفتاح API حقيقيًا في أي ملف، ولا ترسله في لقطة شاشة أو في Git.

## 1. إصدار Python

تم التشغيل على هذا الجهاز باستخدام:

- Python 3.12.0
- pip 26.1
- Tkinter 8.6 (مكتبة قياسية، ليست حزمة pip)
- requests 2.32.3
- Pillow 12.2.0

لا توجد بيئة افتراضية داخل المشروع.

## 2. الاعتماديات

من `requirements.txt`:

- `requests` للطلب HTTP
- `Pillow` لفتح صور الخلفية وأيقونة البحث

من مكتبة Python القياسية، ويستخدمها `weather_app.py` فعلًا:

- `tkinter`
- `threading`
- `datetime`
- `time`

لا تثبّت Tkinter عبر pip. على Windows يكون مرفقًا مع مثبّت Python الرسمي. إذا فشل `import tkinter` فالمثبّت نُفّذ من دون خيار Tcl/Tk.

`D:\project_lv3\Python-Weather-Info-App-main`

تأكد أن الأمر التالي يطبع إصدارًا يبدأ بـ `Python 3`:

## 4. إعداد مفتاح API

1. أنشئ حسابًا على OpenWeatherMap.
2. أنشئ مفتاحًا من صفحة المفاتيح: https://home.openweathermap.org/api_keys
3. احتفظ بالمفتاح عندك. هذه النسخة لا تحتوي مفتاحًا صالحًا داخل الملفات.

## 5. التعامل الآمن مع المفتاح

المشروع الأصلي كان يضع المفتاح في السطر `API_KEY = "..."` داخل `config.py`. هذه النسخة التعليمية تقرأه من متغير البيئة `OPENWEATHER_API_KEY`.

في PowerShell، من الجلسة نفسها التي ستشغّل البرنامج:

```powershell
$env:OPENWEATHER_API_KEY = "your_key_here"
```

في موجه أوامر Windows:

```bat
set OPENWEATHER_API_KEY=your_key_here
```

`your_key_here` نص توضيحي فقط. استبدله بمفتاحك داخل الطرفية، لا داخل الملفات.

إذا لم يُضبط المتغير، يستخدم `config.py` النص `YOUR_OPENWEATHERMAP_API_KEY`. هذا ليس مفتاحًا صالحًا. الطلب عندها يرجع HTTP 401، والواجهة تعرض:

`Provide a valid city name to get info`

هذه الرسالة نفسها تظهر لمدينة خاطئة ولمشكلة الشبكة، لأن البرنامج يلتقط كل الاستثناءات في `except Exception`.

لا تكتب المفتاح في:

- `config.py`
- `README.md`
- هذا الدليل
- لقطات الشاشة
- سجل Git

إذا كان مفتاح قديم موجودًا في نسخة المصدر التي عندك، ألغِه من لوحة OpenWeatherMap وأنشئ مفتاحًا جديدًا.

## 6. التثبيت

من مجلد المشروع:

```powershell
python -m pip install -r requirements.txt
```

على الجهاز الذي نُفّذ عليه الاختبار كانت الحزمتان مثبتتين مسبقًا، ولم يُحتج إلى بيئة افتراضية.

## 7. أمر التشغيل

يجب أن يكون مجلد العمل هو مجلد المشروع، لأن مسارات الصور نسبية (`assets/...`).

```powershell
cd D:\project_lv3\Python-Weather-Info-App-main
$env:OPENWEATHER_API_KEY = "your_key_here"
python weather_app.py
```

لا تشغّل الملف من مجلد أب. عند التجربة من `D:\project_lv3` توقف البرنامج فورًا برمز خروج 1 وهذا الخطأ:

`_tkinter.TclError: bitmap "assets/weather.ico" not defined`

السبب في السطر 103 من `weather_app.py`: `app.iconbitmap("assets/weather.ico")` خارج `try`. معالج الصورة المفقودة في `set_background()` لا يصل إليه.

## 8. مدينة للاختبار

المدينة الافتراضية في `config.py` هي `New Delhi`. عند الفتح الناجح تظهر في صندوق الإدخال وفي النص:

`City: New Delhi, IN`

مدينة ثانية جُرّبت بنجاح: `London`. النتيجة تكون بالشكل:

`City: London, GB`

درجة الحرارة تتغير لأن البيانات حية. في اختبار 28 سبتمبر 2026 كانت لندن حوالي 12.9°C، وهذا Celsius لأن الطلب يرسل `units=metric`.

## 9. اختبار مدينة غير موجودة

اكتب `NotARealCityXYZ` ثم اضغط Search.

النتيجة التي ظهرت فعلًا:

`Provide a valid city name to get info`

الواجهة لا تعرض النص `Not Found. Please provide a valid city name.` مع استجابة OpenWeather الحالية، لأن الحقل `cod` في حالة 404 يرجع كنص `"404"` بينما الشرط في الكود يقارنه بالعدد `404`.

## 10. الناتج المتوقع

عند نجاح الطلب يظهر صندوق المعلومات بهذا الترتيب:

- City: اسم المدينة ورمز الدولة
- Temperature: رقم متبوعًا بـ `°C`
- Weather: وصف إنجليزي، أول حرف كبير
- Pressure: رقم ثم `hPa`
- Humidity: رقم ثم `%`
- Wind Speed: رقم ثم `m/s`
- Sunrise و Sunset بصيغة `HH:MM:SS`

أوقات الشروق والغروب تُحسب بتوقيت جهازك المحلي، لا بتوقيت المدينة. على جهاز الاختبار (توقيت سوريا، UTC+3) ظهر شروق نيودلهي `03:42:12` بينما التوقيت العالمي كان `00:42:12` وتوقيت الهند `06:12:12`.

قبل ظهور النتيجة يبقى الزر معطلًا ونصه `Searching`، ويظهر `Loading` لنحو 3 ثوانٍ بسبب `time.sleep(3)` ثم زمن الشبكة.

الصور المتوقعة عند التشغيل من المجلد الصحيح:

- أيقونة النافذة من `assets/weather.ico`
- الخلفية من `assets/background.png`
- أيقونة العدسة من `assets/search_icon.png`

## 11. أخطاء شائعة

| ما يحدث | المعنى |
| --- | --- |
| `Provide a valid city name to get info` | مدينة غير موجودة، أو مفتاح مرفوض (401)، أو انقطاع الشبكة، أو رمز `#` داخل النص كسر الرابط |
| `Enter city name to get weather info` | صندوق المدينة فارغ. لا يُرسل طلب |
| HTTP 401 و `cod` عدد صحيح | المفتاح مفقود أو غير صالح |
| HTTP 404 و `cod` نص `"404"` | المدينة غير موجودة عند OpenWeather |
| HTTP 400 ورسالة `Nothing to geocode` | طلب بلا اسم مدينة. الواجهة تمنع هذا إذا كان الصندوق فارغًا |
| `TclError` على `weather.ico` | التشغيل من مجلد عمل خاطئ |
| نافذة خطأ `Background image not found!` | ملف الخلفية نفسه مفقود. هذا المسار فقط داخل `set_background()` |

تجربة إضافية: ثلاثة فراغات `"   "` لا تُعد إدخالًا فارغًا. الواجهة أرسلتها، وOpenWeather أرجع مدينة `Xankandi` في `AZ`. البرنامج لا ينفّذ `strip()`.

النص الابتدائي `Enter city name here` يُستبدل عند نجاح مدينة افتراضية. إذا بحث المستخدم عنه كما هو، يظهر كأنه اسم مدينة ويرجع رسالة الخطأ العامة.

## 12. استكشاف الأعطال

1. شغّل الأمر من مجلد المشروع، لا من مجلد أعلى.
2. تأكد أن `OPENWEATHER_API_KEY` مضبوط في نفس نافذة الطرفية. المتغير لا ينتقل إلى نافذة قديمة.
3. تأكد أن المفتاح مفعّل في حساب OpenWeather. المفاتيح الجديدة قد تتأخر دقائق قبل أن تعمل.
4. إذا بقيت الرسالة العامة، جرّب مدينة معروفة مثل `London`. إذا فشلت هي أيضًا فالمشكلة غالبًا المفتاح أو الشبكة، لا اسم المدينة.
5. البرنامج لا يضبط `timeout` في `requests.get()`. الشبكة المتوقفة قد تترك الزر على `Searching` حتى يرجع الخطأ أو ينجح الطلب.
6. الإغلاق أثناء الطلب لا يوقف الخيط. الخيط ليس `daemon`، وقد يحاول تعديل واجهة أُغلقت.
7. على هذا الاختبار نجح التشغيل على Windows 10. استدعاء `iconbitmap` مع ملف `.ico` خاص بويندوز، ولم يُختبر macOS أو Linux هنا.
