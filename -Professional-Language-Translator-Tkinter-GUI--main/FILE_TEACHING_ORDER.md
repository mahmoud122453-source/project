## لماذا `translator.py` أولًا

كل السلوك قابل للقراءة في هذا الملف: إنشاء الكائن، القائمة، الترجمة، المسح، والتشغيل. README يصف المشروع، لكنه كان يحتوي تعليمات استنساخ غير مطابقة للمستودع ووصفًا غير دقيق لواجهة الترجمة. الكود هو المرجع.

## ماذا يُؤجَّل داخل الملف نفسه

- تفاصيل `style.configure` في الأسطر 31–41. الطالب يعرف ttk. تُعرض مرة واحدة بعد عمل الترجمة.
- المتغيرات المحلية مثل `header` و`btn_frame`. لا تُستخدم بعد بناء الواجهة.
- لا يوجد في الملف نموذج عصبي أو تقييم جودة ترجمة. لا تُضاف هذه الموضوعات إلى الدرس.

## ترتيب `README.md` بعد الكود

1. الوصف والميزات: طابِقها مع الواجهة الفعلية. القائمة لغة هدف فقط.
2. التقنيات: Python و Tkinter و ttk و `googletrans`.
3. التثبيت والتشغيل: الإصدار `googletrans==4.0.0-rc1` ثم `python translator.py`.
4. جدول الرموز: هو نفسه قائمة Combobox.
5. الملاحظات: الإنترنت مطلوب.
6. قسم Future Improvements: خطط المؤلف، وليست سلوكًا موجودًا. بند Auto Language Detection لا يعني أن الكود الحالي يعرض لغة مكتشفة. الاكتشاف الصامت موجود لأن `src` غير ممرَّر.
7. المؤلف وخاتمة الترخيص التعليمية: تُحفظ كما هي.
